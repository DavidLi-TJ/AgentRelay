# AgentRelay 用户指南

按实际使用顺序，把每个界面、每个操作讲清楚。架构与格式细节见 [format-notes.md](format-notes.md)，MCP 工具见 [MCP.md](MCP.md)。

## 1. 安装与启动

需要 **Windows 10/11**（已完整验证；macOS/Linux 存储路径已就绪、尚未广泛实测，欢迎反馈）和 **Node.js 22.5+**（使用内置 `node:sqlite`）。无需安装任何东西——零依赖、零构建。

三种启动方式：

```bash
npx @ldavidl/agentrelay serve        # 一条命令，无需克隆仓库
# 或者克隆后：
node server/index.js                          # 或双击 StartAgentRelay.bat（Windows）/ 运行 ./start.sh（Linux/macOS）
```

浏览器会打开 `http://127.0.0.1:17777`，服务只监听本机。如果端口被占用，设置环境变量 `AGENTRELAY_PORT=17778`（或任意空闲端口）再启动。

顶栏从左到右：服务状态灯、中/EN 语言切换、主题切换、**刷新**按钮（清空会话列表缓存并重新扫描全部 agent）、**电源**按钮（干净地关闭服务）。

## 2. 首次运行

首次打开会出现向导，问三件事：语言、主题、**数据目录**（默认 `~/.agentrelay`）。这个目录存放 AgentRelay 自己的文件（配置、备份、导出、缓存、日志）——你的会话永远不在这里，它们始终保存在各个 agent 自己的存储里。

向导结束后，AgentRelay 检测本机存在哪些 agent，并显示各自的实时会话数。在设置里停用的 agent 完全不会被扫描。

## 3. 会话视图

主界面：**左侧 agent 栏、中间会话列表、右侧逐字预览。**

- **Agent 栏** — 每个 agent 一张卡片，带会话数。点击即浏览该 agent。列表与预览之间有一条可拖动的窄把手，可以调整两栏宽度。
- **搜索框** — 输入即按标题/项目路径过滤；按 **回车** 对会话正文做全文搜索。
- **查重** — 跨所有 agent 找出"标题 + 规模 + 项目"相同的会话（迁移测试常会留下副本），一键跳到每个副本。
- **预览** — 完整会话逐字呈现：用户与助手正文、工具调用及其输入与结果、思考块、系统注入。大会话每次只渲染约 400 条，用**前 400 条 / 后 400 条**翻完整个会话，不主动加载就不会占内存。

预览里可以：

- **预览内搜索** — 预览上方的搜索框会高亮命中并显示本屏命中数。
- **勾选条目** — 每条带复选框，也可用选择栏的全选/全不选。勾了什么，接力就带什么。
- **导出** — **导出 MD** 把会话渲染成逐字 Markdown 转写（选择与脱敏照常生效；工具调用与思考块渲染为围栏/可折叠区块）；**导出 ARX** 写出结构化 JSON 中间格式，供备份或日后重新装回。
- **微调选择** — 预览上方的选择栏集中了所有开关：是否携带思考块 / 工具结果 / 系统注入、密钥脱敏、起始条目偏移、工具输出截断（KB）、token 上限（**1M / 512K / 200K** 预设），以及**从最近压缩点开始**——从源 agent 最新的压缩边界接力，目标收到的正是源 agent 脑中还记着的部分。
- **查看子代理会话** — 产生了子代理的会话（目前是 ZCode）会在父会话头部折叠展示，点开即可阅读，条目过多时框内可滚动。

**快启动，自己决定。** 设置 → "启动时自动加载全部会话列表"。开启：页面打开即扫描全部 agent。关闭：页面秒开，点哪个 agent 才扫描哪个。两种模式下，上次已知列表都会走本地缓存（24 小时）即时显示，再在后台静默刷新。顶栏**刷新**按钮会丢弃缓存、强制全量重扫。

## 4. 编辑上下文

会话会"跑偏"：agent 循环输出"let me do it"、一条工具结果污染了后面所有上下文、一步走错满盘皆输。打开会话，点击预览头部的**编辑模式**。

可以做的事：

- **按关键词过滤条目**，快速定位垃圾内容。
- **删除**条目；**就地改写**任意条目的文本。
- **插入**新条目：用户消息、助手消息、完整的工具调用对（保持相邻——原因见下方注意事项），或**粘贴从其他 agent 导出的 ARX 片段**，把整段上下文批量合并进来。
- **逐字复制**任意条目（贴进文档、issue 或另一个 agent）。
- 批量勾选后可对所选统一操作。

保存提供两种模式：

| 模式 | 适用 | 行为 |
|---|---|---|
| **另存为新会话** | 所有 agent | 在该 agent 存储里写一个全新会话，原会话不动。 |
| **就地保存** | Claude Code、ZCode | 覆盖会话自身存储。写前自动备份（诊断页可还原），下次该 agent 打开会话时生效。 |

几点如实说明，免得意外：

- 编辑器能触达**已加载的前 400 条**；先点"后 400 条"把更后面的条目带进来再编辑。
- `tool_result` 若远离配对的 `tool_use`，可能导致 `claude --resume` 失败。编辑器因此强制让粘贴的工具对保持相邻——也不要单独删除配对的一半。
- Claude 就地保存会重新合成转写。sidechain（子代理）、attachment、元数据行原样保留在原位；只有锚点条目被你删除的行会顺延到文件末尾。自动备份仍是恢复路径。
- 编辑永远因为你**亲手点击**才发生。接力绝不修改源会话。

## 5. 接力视图——主流程

三步：**选源 → 选目标 → 执行。**

1. **来源。** 在会话页勾选的会话已经在这里待命，可继续增删。
2. **目标。** 点击目标 agent 卡片，徽标会标出**推荐的接力档位**并解释原因。然后用文件夹浏览器选择**目标项目目录**——接力过去的会话将绑定到该项目，这正是它能被 resume 的前提。
3. **执行。** 先点 **Dry-run 预览**：完整走一遍流程但不写盘，报告将写入的确切路径、条数、token 估算和每一条转换说明。看完点**开始接力**，确认后自动备份 → 写入 → 结果面板给出目标 agent 的 resume 命令。

三个档位，简版：

| 档位 | 何时使用 | 含义 |
|---|---|---|
| **T0** | 同 agent → 自身 | 原生复制：新会话 id、重建消息链、重写 cwd。100% 无损。 |
| **T1** | 其他受支持目标（默认） | 合成目标 agent **自己的**会话格式写入其原生存储并注册，resume 或会话列表直接可见。 |
| **T2** | 兜底 | 把完整会话作为逐字转写写进目标项目并附启动提示词。万能，但不是原生会话。 |

每次接力的结果都带**保真清单**——档位、保留的条目/工具/思考计数、全部省略项——动了什么、没动什么，一目了然。

## 6. 跨设备接力（.arxbundle）

会话在一台机器上，工作在流动。接力页底部：

1. **导出** — 选好源会话后点打包按钮。可先开启脱敏，把密钥/凭据在打包前抹掉。一个 `.arxbundle` 文件会落到数据目录的 exports 文件夹。
2. **带走** — U 盘、网盘、任意渠道。文件是纯本地 JSON，不会上传到任何地方。
3. **导入** — 在另一台机器上：点*读取清单*查看包内会话，目标 agent 沿用上方第 2 步选的卡片；AgentRelay 会列出包内出现的每个项目路径并留出"本机路径"输入框（**路径重映射**——正是这一步让 T1 会话在新机器上可 resume）。点**导入并接力**，同样支持先 dry-run。

CLI 等价操作：

```bash
node cli.js bundle out.arxbundle --from claude:<id> --from codex:<id> --redact
node cli.js import-bundle out.arxbundle --to codex --remap "D:/work=/Users/x/work" --dry-run
```

## 7. 活动视图

每一次接力、备份、设置变更都记录在这里，最新在前，可按级别过滤（`error` / `warn` / `info` / `debug` / `trace`）。行为异常时，这就是要带走的线索。日志文件自动瘦身：超过 5MB 只保留最新 2MB。

## 8. 诊断

- **存储健康** — 每个 agent 一块面板：存储是否可达、体积多大、会话多少。
- **备份管理** — 列出所有写前自动快照，保留最近 20 份。还原前会先把*当前*状态再备份一份，所以还原本身也可逆。
- **诊断包** — 导出存储统计与近期日志，**不含会话内容**；报 GitHub issue 时附上，解决问题快得多。

## 9. 设置

- **Agent 实例** — 内置 agent 可逐个启停。WorkBuddy 出厂即两张卡：**国内版**（`~/.workbuddy`）与**国际版**（`~/.workbuddy-ai`），各自锁定目录、绝不混扫。*添加实例*可为同类型 agent 登记额外的存储位置（比如两个 Claude 配置目录），填显示名和数据目录；*检测*按钮先验证路径再加。
- **通用** — 语言、主题（暗色/亮色/跟随系统）、字体大小、日志级别。
- **背景图片** — 填本地图片路径或 https 链接，即时生效且跨重启持久保存。*毛玻璃强度*滑杆控制面板在壁纸上的磨砂程度。清空输入框则回到纯色背景。
- **数据目录** — 备份、导出、缓存、日志的存放位置。修改后新文件写入新位置，旧文件原地不动。
- **写前自动备份** 开关（建议保持开启）。
- **启动时自动加载全部会话列表** — 见 §3。
- **启动时检查新版本** — 默认关闭；开启后启动时只发一次 GitHub API 请求。

## 10. MCP——在 agent 内部接力

注册一次：

```bash
claude mcp add agentrelay -- node C:\path\to\agentrelay\cli.js mcp
```

之后直接在对话里让 agent 替你接力。七个工具：`list_agents`、`list_sessions`、`search_sessions`（跨全部 agent 的会话正文全文搜索）、`get_session`、`preview_transfer`、`transfer`、`doctor`。`transfer` 不传 `confirm: true` 时始终是 dry-run。完整参考：[MCP.md](MCP.md)。

## 11. CLI 参考

| 命令 | 作用 |
|---|---|
| `node cli.js agents` | 列出检测到的 agent 与会话数 |
| `node cli.js list <agent> [--q 关键词]` | 列出会话（`--json`、`--verbose`） |
| `node cli.js show <agent> <sessionId>` | 打印会话前若干条（`--limit`） |
| `node cli.js export <agent> <sessionId>` | 按 ARX JSON 或 Markdown 导出（`--out`、`--format md`、`--from/--to`、`--no-thinking`、`--truncate`、`--budget`、`--redact`） |
| `node cli.js load <file.arx.json> --into <agent> --cwd <路径>` | 把先前导出的 ARX 文件装回 agent（`--mode`、`--dry-run`） |
| `node cli.js transfer --from <agent>:<id> --to <agent>` | 一次性接力（`--cwd`、`--mode T0/T1/T2`、`--dry-run`） |
| `node cli.js bundle <out> --from <agent>:<id> [...]` | 跨设备打包多个会话（`--redact`） |
| `node cli.js import-bundle <file> --to <agent>[@<cwd>]` | 导入 bundle（`--remap 旧=新`、`--mode`、`--dry-run`） |
| `node cli.js doctor` | 存储健康 JSON |
| `node cli.js serve` | 启动 Web GUI |
| `node cli.js mcp` | 启动 stdio MCP 服务 |

## 12. 性能、资源与磁盘

AgentRelay 就是几个 Node 内置模块加一个静态页面——服务空闲时几乎零开销。为保持轻量已经做了：大会话分页渲染而非全量铺开、会话列表本地缓存使启动免重扫、活动日志自动瘦身、exports 只保留最新 50 个文件。想要最轻启动，关掉自动加载（§3），按需扫描即可。

## 13. 故障排查

<details>
<summary>端口被占用</summary>
设置 <code>AGENTRELAY_PORT</code> 为空闲端口后重新启动。
</details>

<details>
<summary>接力过去的会话在目标 agent 里没出现</summary>
检查 dry-run 输出：报告的路径必须位于目标 agent 的真实存储内。关闭并重新打开目标 agent（其会话列表可能缓存在内存中），或直接用结果面板给出的 resume 命令。Cursor：向其写入时 Cursor 必须<strong>完全关闭</strong>——它的内存态可能在退出时覆盖外部写入。
</details>

<details>
<summary>DeepSeek Harness 作为目标没反应</summary>
对 DSH 的原生（T0/T1）写入需要 Node ≥ 23.8 内置的 zstd 支持。旧版 Node 上界面会自动降级为 T2。
</details>

<details>
<summary>Trae / 豆包工作支持吗？</summary>
Trae 用 SQLCipher 加密其 agent 数据库，密钥在 Trae 自己的后端内生成，因此没有安全的原生写入路径；豆包工作的会话正文在其应用内 IndexedDB/云端，没有本地会话库。两者都可走 T2 接力（逐字转写 + 启动提示词写进目标项目文件夹）——把提示词粘贴到那边的新会话/工作任务即可。
</details>

<details>
<summary>出错了能撤销吗？</summary>
每次写入既有存储前都会先备份（SQLite <code>VACUUM INTO</code> 快照或文件拷贝），最近 20 份列在诊断页，一键还原。
</details>

<details>
<summary>数据会离开我的电脑吗？</summary>
不会。读写全部发生在本机磁盘；无遥测、无网络请求，除非你开启更新检查——那也只是一次 GitHub API 请求。
</details>

## 14. 数据都存在哪里

| 路径 | 内容 |
|---|---|
| `~/.agentrelay/`（或自定义数据目录） | 配置、备份、导出、会话列表缓存、日志 |
| `~/.claude/projects/`、`~/.codex/`、`~/.zcode/cli/db/`、… | 会话本体——始终在各 agent 自己的存储里 |

AgentRelay 读取这些存储，并只在你明确下令时写入目标存储。它从不移动、占有或悄悄修改任何会话。
